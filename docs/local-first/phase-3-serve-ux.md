# Phase 3 spec — serve UX, secrets bootstrap, multi-instance ergonomics

**One PR against `develop`.** Implements Phase 3 of
`docs/local-first-single-process.md`: secrets auto-generation, shared env
root, opt-in access token, and serve polish (network-FS check, `backup`
command, startup URL printing). No migrations. No OpenAPI changes expected
(new surface is CLI, middleware, settings layering) — run
`pixi run generate-api-types` once to confirm. Touches
`src/ai_almanac/server/`, so `/security-review` is required before push.

## Design decisions

**D1 — Secrets load as a new layer inside `reload_settings()`; generation
happens once, in the server lifespan.** Loading must live in
`reload_settings()` (`settings.py`), not only in `serve`, because every
detached process re-resolves settings through it (`execute-job` /
`run-job-workload`), and those must unseal `cdsapi_key`/`llm_api_key` from
the `app_config` overlay. Layer order becomes: **defaults < secrets.env <
config.yaml < DB overlay < env** — `_apply_overlay`'s existing
`key.upper() in os.environ` check gives env vars final say, so cloud deploys
(which set `CREDENTIAL_ENCRYPTION_KEY`/`CHAT_FIGURE_SIGNING_SECRET` from
Secret Manager; see `terraform/modules/almanac-env/main.tf`) see zero change.
secrets.env sits *below* config.yaml so operator-set values stay
authoritative. Generation is gated to `deployment_mode == "personal"` and
runs in `app.py`'s lifespan (and once from `cli.serve`), never from bare
`reload_settings()` — tests, `db upgrade`, and shared deployments don't
silently mint keys. The existing double-`_reload_user_config()` in the
lifespan handles unseal ordering: reload #1 may drop sealed overlay values,
the bootstrap ensures the key, reload #2 unseals correctly.

**D2 — `AI_ALMANAC_ENV_ROOT` is an env var resolved in `paths.py`, not a
`Settings` field.** `paths.py` is imported by `settings.py` (circular
otherwise), env paths are needed before settings resolve, and detached job
processes inherit `os.environ` (job_manager spawns with no `env=` kwarg).
Mirrors `AI_ALMANAC_DATA_DIR` exactly.

**D3 — Token auth is a standalone middleware gate, orthogonal to
`auth_mode`.** `_resolve_identity` stays untouched — the token is a bearer
*gate*, not an identity. Scheme: `?token=` on a GET → `Set-Cookie`
(HttpOnly, SameSite=Lax) + redirect stripping the query param; thereafter
cookie or `Authorization: Bearer`. `web/src/lib/api/core.ts` uses bare
`fetch()` (default `credentials: 'same-origin'`), so the cookie flows
automatically — **zero frontend changes** for the packaged serve.
`enforce_cookie_csrf` only fires in shared mode; in personal+token mode,
SameSite=Lax blocks cross-site cookie-bearing POSTs.

**D4 — Network-FS check: warn always; refuse when the DB is
SQLite-on-network unless `--allow-network-data-dir`.** SQLite on NFS is the
corruption case; a network data dir with Postgres is merely slow.

## New files

### 1. `src/ai_almanac/locking.py` (~30 lines)

```python
@contextmanager
def file_lock(path: Path, message: str | None = None): ...
```

`fcntl.flock(LOCK_EX)` on `path` (created if absent). Try `LOCK_EX |
LOCK_NB` first; on `BlockingIOError`, log `message` then block. On
`ImportError` (Windows), degrade to no-op with a debug log. Shared by
secrets bootstrap and env prepare.

### 2. `src/ai_almanac/secrets_bootstrap.py` (~90 lines)

- `MANAGED_SECRETS`: `credential_encryption_key` →
  `base64.urlsafe_b64encode(os.urandom(32)).decode()` (round-trips through
  `llm_profiles._master_key`); `chat_figure_signing_secret` →
  `secrets.token_urlsafe(32)`.
- `load_secrets_file() -> dict[str, str]`: parse
  `$AI_ALMANAC_DATA_DIR/secrets.env` (`KEY=VALUE`, skip blanks/`#`), return
  managed keys only (map `CREDENTIAL_ENCRYPTION_KEY` →
  `credential_encryption_key`). Missing file → `{}`. Group/other-readable →
  warn and `chmod 0600`.
- `ensure_local_secrets() -> bool`: under `file_lock(secrets.env.lock)`:
  re-read; for each managed field, skip if (a) `FIELD.upper()` in
  `os.environ`, (b) present in file, or (c) effective `settings` value is
  non-default (`""` for the key, `"dev-chat-figure-secret"` for the signing
  secret). Write merged file atomically: `os.open(tmp,
  O_WRONLY|O_CREAT|O_EXCL, 0o600)` → write → `os.replace`. Header:
  `# generated by ai-almanac — do not commit or share`. Returns True if
  anything was written (caller re-runs `reload_settings()`).

### 3. `src/ai_almanac/fscheck.py` (~60 lines)

- `_NETWORK_FS_TYPES = {"nfs", "nfs4", "cifs", "smbfs", "smb2", "9p",
  "fuse.sshfs", "glusterfs", "lustre", "ceph", "afpfs", "webdav", "davfs"}`
- `network_fs_type(path: Path) -> str | None`:
  - Linux: parse `/proc/self/mounts`, longest-mount-point-prefix match;
    return fstype if in the set or `startswith("nfs")`. Factor the parser as
    `_match_mounts(mounts_text, path)` for unit tests.
  - macOS: `ctypes` `statfs(2)` → `f_fstypename` membership.
  - Anything else / any exception: `None` (never block startup on the
    detector).

## Modified files

### 5. `src/ai_almanac/paths.py`

```python
def secrets_env_path() -> Path:
    return data_root() / "secrets.env"

def env_root() -> Path:
    override = os.environ.get("AI_ALMANAC_ENV_ROOT")
    if override:
        return Path(override).expanduser().resolve()
    return data_root()
```

`benchmark_env_dir` / `blending_env_dir` / `forecast_env_dir` derive from
`env_root()` instead of `data_root()`. `ensure_layout()` unchanged.

### 6. `src/ai_almanac/settings.py`

- New field `serve_access_token: str = ""` (env `SERVE_ACCESS_TOKEN`). Add
  to `SENSITIVE_FIELDS`. Deliberately **not** added to `_FIELD_GROUPS` — it
  must not be settable/leakable through the UI (`_SCHEMA_FIELDS` derives
  from the groups, so it's excluded from GET/PATCH automatically).
- In `reload_settings()`, insert the secrets layer between defaults and
  yaml:

  ```python
  fresh = Settings()
  _apply_overlay(fresh, _load_secrets_file())   # env still wins inside _apply_overlay
  _apply_overlay(fresh, yaml_overlay)
  _apply_overlay(fresh, db_overlay)
  ```

  `_load_secrets_file()` lazily imports `secrets_bootstrap` and swallows
  exceptions to `{}` (same posture as `_load_config_yaml`).
- Update the layering docstring/comment block.

### 7. `src/ai_almanac/server/app.py`

- Lifespan: after the first `_reload_user_config()`, call
  `_bootstrap_local_secrets()` — runs `ensure_local_secrets()` when
  `deployment_mode == "personal"`, re-runs `reload_settings()` if it wrote.
  Placed before `_enforce_deployment()`.
- New middleware `enforce_access_token`, **registered last in the file**
  (after `_spa_navigation_fallback`) so it runs outermost:
  - No-op when `not settings.serve_access_token`.
  - Exempt: `/health` only (`/ready` stays gated — it reveals config state).
  - Accept: cookie `almanac_token` or `Authorization: Bearer <t>`, compared
    with `hmac.compare_digest`.
  - `?token=` accepted on GET only: on match, 303-redirect to the same URL
    with the param removed, `Set-Cookie: almanac_token=<t>; HttpOnly;
    SameSite=Lax; Path=/; Max-Age=2592000` (30 days; loopback-only so no
    `Secure`).
  - Rejection: page navigation → tiny inline 401 HTML ("open the URL printed
    in the terminal where `ai-almanac serve` is running"); otherwise
    `JSONResponse({"detail": "Access token required"}, 401)`.
  - `log_requests` logs `request.url.path` only (no query string), so the
    token never hits logs; the redirect strips it from the address bar.

### 8. `src/ai_almanac/envs/manager.py`

Wrap `ensure_env()` (and individually callable `ensure_blending_env` /
`ensure_forecast_env`) in:

```python
with file_lock(env_root() / ".prepare.lock",
               message="another instance is preparing environments in this env root; waiting…"):
```

Concurrent `pixi install` into one manifest dir and concurrent `git clone`
are both unsafe; one coarse lock over the whole prepare is the simple
correct answer. `run`/`run_blending`/`run_forecast`/`env_versions` need no
change — they resolve through `paths` helpers.

### 9. `src/ai_almanac/server/services/bundle.py` — latent bug fix

Line 33 assumes the env dir lives under the data dir:

```python
env["AI_ALMANAC_DATA_DIR"] = str(benchmark_env_dir().parent)
```

With a split env root this points jobs' data dir at the shared env root.
Change to `str(data_root())` and drop the `benchmark_env_dir` import.
`AI_ALMANAC_ENV_ROOT` needs no explicit forwarding — `job_workload.py`
merges over `os.environ.copy()` and the supervisor chain inherits env.

### 10. `src/ai_almanac/cli.py`

- `serve`: add `--token/--no-token` (default off) and
  `--allow-network-data-dir` (default off; also env
  `AI_ALMANAC_ALLOW_NETWORK_DATA_DIR=1`). Flow after `reload_settings()` +
  loopback guard + `ensure_layout()`:
  1. **Network-FS check:** `fs = network_fs_type(data_root())`. Set + SQLite
     DB + not overridden → red error naming fstype + corruption risk +
     override flag, `Exit(2)`. Set otherwise → yellow warning.
  2. **Secrets:** personal mode → `ensure_local_secrets()` +
     `reload_settings()`; print "generated secrets at <path>" on first run.
  3. **Token:** `--token` and empty `settings.serve_access_token` →
     `token = secrets.token_urlsafe(24)`;
     `os.environ["SERVE_ACCESS_TOKEN"] = token` (survives the `--reload`
     subprocess; picked up by the app's env layer). Already configured →
     reuse. Effective token → print/open `{url}?token={token}`.
  4. **Startup print polish:**

     ```
     ai-almanac 0.x serving at http://127.0.0.1:8765/
       data dir: …    env root: …   (only when it differs)
       access token required — open: http://127.0.0.1:8765/?token=…
     ```

- New `backup` command:
  - `reload_settings()`; non-sqlite `resolve_database_url()` → red error
    ("use pg_dump for Postgres"), `Exit(1)`.
  - `dest` default `data_root()/"backups"`; mkdir.
  - `sqlite3.connect(db).backup(...)` to `almanac-{YYYYmmdd-HHMMSS}.db` —
    the online backup API is WAL-safe while the server runs.
  - Copy `config.yaml` and `secrets.env` (if present) to stamped names,
    `chmod 0600` the latter.
  - Print what was written; note uploads/job outputs are not included.
- `env info`: also print `env root: {env_root()}`.

## Test strategy

- **Secrets** (per-test `tmp_path` data dir; `reload_settings()` +
  restore): file created 0600 with both keys; idempotent second call; env
  var set → nothing generated, env value effective; generated key
  round-trips through `llm_profiles.encrypt_api_key`/`decrypt_api_key`;
  config.yaml beats file; shared mode generates nothing; a sealed
  `write_settings_overlay({"llm_api_key": …})` succeeds with only the
  generated key — kills the 400 in `routers/settings.py` for personal
  installs (the regression this feature exists for).
- **Env root**: `AI_ALMANAC_ENV_ROOT` set → three dirs move, `data_root()`
  doesn't; unset → identical to today;
  `build_job_env()["AI_ALMANAC_DATA_DIR"] == str(data_root())` with env
  root set. `file_lock`: two processes serialize.
- **Token** (httpx client fixture with
  `monkeypatch.setattr(settings, "serve_access_token", t)`): API without
  token → 401 JSON; document GET → 401 HTML; `GET /?token=t` → 303 +
  `Set-Cookie`, location without the param; cookie → 200; Bearer → 200;
  wrong token → 401; `?token=` on POST → 401; `/health` exempt; token in no
  response body; empty setting → everything open. `test_auth.py` /
  `test_shared_security.py` stay green (middleware no-ops when unset).
- **Backup**: `CliRunner`; backup file exists and `PRAGMA integrity_check`
  → `ok`; non-sqlite → exit 1.
- **fscheck**: unit-test `_match_mounts` with fixture `/proc/mounts` text
  (nfs4 mount, longest-prefix disambiguation, no match).

## Open questions

1. **Env-var naming**: `SERVE_ACCESS_TOKEN` follows the repo's unprefixed
   convention (`LLM_API_KEY`), but an `AI_ALMANAC_` prefix is safer against
   ambient collisions. Pick a convention.
2. **Cookie lifetime**: 30 days proposed; session-only is stricter but
   forces re-pasting the token URL every browser restart.
3. **Refuse vs warn** on network FS with SQLite: refuse with override flag
   proposed.
4. **DNS-rebinding hardening** (Jupyter checks `Host`): out of scope
   (loopback + token); note in the middleware docstring.
5. **`ai-almanac reset`** deletes `data_root()` only; with a shared env
   root the envs survive a reset. Intended — but `reset` should say so.
6. **Backup scope**: DB + config + secrets only (no uploads/jobs tarball).
