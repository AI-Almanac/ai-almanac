PR Review Pipeline

ai-almanac · design doc · adapts Anthropic's multi-gate, separate-context review model to a solo maintainer with subscription-only Claude auth
Core principle (from Anthropic's SDLC post): separate the four jobs — create, check, authorize, deploy. Deterministic tools prove what machines can prove; AI reviewers with independent context windows reason about what they can't; a human owns authorization.

3AI review gate — two independent agentsAI agent

Two separate workflow jobs = two separate context windows. Neither sees the other's reasoning, so an anchored or manipulated context can't clear both gates.

claude-review.yml · general reviewer

  • Trigger: every non-draft PR to develop, docs-only diffs skipped
  • Prompt encodes project checklist: API-type regeneration, Python weekday (Mon=0) convention, SQLite migration discipline, data-source ownership boundaries, ROMP/blend config correctness
  • Output: one sticky PR comment, updated per push

claude-security-review.yml · security reviewer

  • Trigger: only PRs touching src/ai_almanac/server/**, terraform/**, .github/**, modal/**, deploy/**
  • Prompt: injection, authz on data sources, path/gs:// validation (SSRF), secrets exposure, workflow-injection in Actions
  • Output: severity-ranked findings comment
4Authorize — mergeHuman

You read both AI reviews and the deterministic results, then merge. Branch ruleset on develop: PR required, checks required, force-push blocked, no approval count (solo). main additionally restricts pushers. AI reviews start report-only; promote "review completed" to a required check once trusted.

5Deploy — scoped machine identityPlatform

Unchanged: merge to develop → staging, merge to main → prod, via GitHub Actions with keyless WIF OIDC. The deploy identity can deploy but cannot approve or author. Post-deploy verification is covered in design-deploy-verification.html.

Quota reality: the OAuth token draws from your personal seat allowance. Guardrails: skip drafts and docs-only diffs, concurrency-cancel superseded runs on force-push, cap --max-turns, path-filter the security job. Expected steady-state: 1–2 agent runs per PR.

Workflow sketch (general reviewer)

name: claude-review
on:
  pull_request:
    branches: [develop]
    paths-ignore: ["docs/**", "**/*.md"]
concurrency:
  group: review-${{ github.event.pull_request.number }}
  cancel-in-progress: true
permissions:
  contents: read
  pull-requests: write
  issues: write
jobs:
  review:
    if: "!github.event.pull_request.draft"
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@<sha>
        with: { fetch-depth: 0 }
      - uses: anthropics/claude-code-action@<sha>
        with:
          claude_code_oauth_token: ${{ secrets.CLAUDE_CODE_OAUTH_TOKEN }}
          prompt: |
            Review this PR diff for ai-almanac. Focus on:
            - correctness and test coverage of changed behavior
            - api-types.gen.ts regenerated if API routes changed
            - weekday numbering uses Python convention (Mon=0)
            - SQLite migration safety (backward compatible)
            - data-source ownership / authz boundaries respected
            Post ONE review comment; be concise; severity-tag findings.
          claude_args: "--max-turns 12"

The security workflow is identical in shape: different paths filter, security-focused prompt, separate job → separate context window.

Failure modes considered

RiskMitigation
Prompt injection via PR content steering the reviewerReviewers have read + comment permissions only; no write to code; deploy identity separate; human merge required.
Review spam / quota burn on rapid pushesConcurrency cancellation, draft skip, turn caps.
Rubber-stamping (trusting AI review too much)Report-only period first; findings are severity-tagged so you can calibrate against reality before making anything blocking.
Token leakRepo secret, never echoed; calendar-based rotation; token scopes to Claude usage only, not GitHub.
